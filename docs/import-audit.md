# DOCX 导入链路审计与整改说明

## 审计目标

本次审计以“原文不能静默消失”为核心约束，覆盖 DOCX 读取、OOXML 顺序还原、题目边界、表格、自动编号、图片、集中答案区、模型请求、结果校验、数据库提交与用户报告。

结论：旧链路适合作为早期实验代码，不适合作为可靠导入入口。当前普通用户入口已切换为标准离线导入与完整文档智能识别两条独立链路，并引入统一来源块、完整账本和持久化报告。旧的对比入口、运行时开关和生产分支已经删除；少量旧辅助类型仅供既有单元测试使用，无法从普通导入路由进入。

## 旧链路的主要风险

### 1. 同一文档被重复读取

旧的对比策略先走可见结果链路，再重新解压并运行另一套解析，造成重复 I/O、重复解析和难以复现的中间状态；对比路径还可能产生额外模型调用。用户看到的结果与后台比较结果并非同一份中间表示。

### 2. 过早压平成纯文本

段落、表格单元格、自动编号、图片关系和不支持的 OOXML 节点被过早折叠，导致以下信息缺口：

- Word 自动编号没有稳定的题号来源。
- 表格行列关系消失，题干、选项和答案可能错配。
- 图片归属依赖占位符与猜测，且多处只取第一张图片。
- 文本框、嵌入对象等内容可能既不成题，也不进入失败报告。

### 3. 正则切块存在泄漏边界

旧 `splitBlocks` 依赖可见题号，标题、说明、集中答案区、无题号题目、一段多题和跨段题目容易被误分。只有“本地解析失败”的片段才进入后续步骤，因此本地误判为成功的题目不会再获得文档级校验。

### 4. 模型只看到孤立失败片段

旧智能兜底缺少完整上下文：

- 无法把文档末尾答案表与前文题目可靠关联。
- 一个片段被强制按一道题处理，一段多题可能合并或只保留第一题。
- 长内容被截断后缺少字符范围与上下文重叠。
- 已被本地解析器接受、归为非题目或未分配的内容完全不进入模型视野。

### 5. 失败可能只计数，不可追溯

API 返回 `null`、无效 JSON、本地校验拒绝或未匹配内容时，旧结果缺少统一的来源账本、稳定原因码和持久化原文。用户无法逐条回答“这段原文最终去哪了”。

### 6. 创建与清理边界不清晰

旧流程在识别、写库和图片处理之间缺少明确的预览/确认边界。失败或取消时，题库数据、临时图片和导入日志可能具有不同生命周期。

## 当前整改

### 一次读取与统一来源

`ImportRepository.prepareImport()` 为每次选择创建唯一任务目录，并通过 `DocxArchiveLoader` 与 `OoXmlDocumentReader` 读取一次。之后两种识别方式都复用同一个 `StructuredDocument` 和 `ImportSourceBlock` 列表，不再从 URI 二次读取。

每个来源块保留稳定 ID、文档顺序、原文、自动编号、表格位置、全部图片关系、字符范围和不支持原因。表格以单元格为来源块，不再仅投影为空文本或丢掉坐标。

### 两种模式完全分离

| 行为 | 标准格式导入 | 智能识别混乱格式 |
|---|---|---|
| 解析方式 | 本地确定性规则 | 完整文档分段模型识别 |
| 读取 API Key | 否 | 用户确认调用时才读取 |
| 网络请求 | 无 | 有，按模型档位调用 |
| 主要场景 | 按模板整理的题库 | 自动编号、表格、集中答案等复杂结构 |
| 失败处理 | 报告原文与格式原因 | 报告原文、模型/API/校验原因 |

标准模式不会因格式失败自动转入智能模式。智能模式也不会以标准解析的成功/失败结果筛选输入。

### 完整来源账本

`SourceLedger` 要求每个非空来源块最终落入以下状态之一：

- `ACCEPTED_QUESTION`
- `REJECTED_QUESTION`
- `NON_QUESTION_CONTENT`
- `UNSUPPORTED_CONTENT`

报告构造时同时校验候选题数量守恒（接受数 + 拒绝数）与账本完整性。未覆盖来源会以 `SOURCE_NOT_COVERED` 或 `SOURCE_LEDGER_INCOMPLETE` 暴露，而不是被忽略。

### 文档级智能识别

智能模式让所有非空来源块进入边界阶段，并把自动编号、表格坐标、图片引用和字符范围一并发送。长文档切片保留相邻重叠；超长单块按字符范围拆分。边界响应允许一个块返回多道题，集中答案区会作为结构阶段上下文。

模型输出只有通过来源追溯、答案归属、题型、选项、重复题和编造内容校验后才会成为题目。成功响应按请求内容缓存；失败响应不缓存。

### 多图与不支持内容

题干和每个选项都可保存有序图片 URI 列表，同时保留旧的首图字段以兼容已有数据。位图在后台按尺寸采样加载，避免直接解码大图。EMF、WMF、文本框和嵌入对象等当前无法可靠展示或解析的结构会进入警告或不支持记录。

### 预览、提交与持久化

识别结束先展示报告，用户确认后才创建题库。提交阶段移动图片、写入题目并保存报告记录；异常时删除刚创建的题库并清理临时目录。取消或页面销毁会使当前操作代次立即失效并在后台清理临时文件，迟到回调不会覆盖后续任务；应用启动还会清理上次进程遗留的任务目录。

持久化报告包含来源 ID、原题号、原文、状态、原因码、说明、创建后的题目 ID、是否尝试 API，以及整次导入的图片、表格、逻辑模型批次和警告统计。

## 典型泄漏点闭环

| 旧风险 | 当前处理 |
|---|---|
| 题目前标题被忽略 | 标记为非题目内容 |
| 文件末尾最后一题未收束 | 解析结束显式完成当前题 |
| Word 自动编号不可见 | 读取编号定义并保留编号来源；无法还原则明确拒绝 |
| 表格结构压平 | 保留表格 ID、行、列和单元格顺序 |
| 集中答案区孤立 | 智能边界阶段识别，结构阶段携带答案区来源 |
| 一段多题只留一道 | 响应协议使用题目数组并允许多候选 |
| 长片段截断后失去位置 | 字符范围切片 + 相邻上下文重叠 |
| 本地“成功”绕过智能识别 | 智能模式不使用本地结果做门控 |
| 只保存第一张图片 | 题干与选项保存完整图片列表 |
| 模型编造内容入库 | 字段必须可从声明来源追溯 |
| 模型跨分段借用另一个真实来源 | 所有来源 ID 限制在本次实际请求范围，字段来源还必须属于题目来源集合 |
| `null`/坏 JSON 静默跳过 | 稳定原因码、原文和来源写入报告 |
| 未分配 OOXML 内容消失 | 来源账本完整性检查 |
| 重试重复计费 | 仅缓存成功响应，相同成功请求复用 |
| 取消后临时图片残留 | 任务级目录清理 |
| 取消后迟到回调覆盖新任务 | `CancellationException` 向上传播 + 操作代次校验 |
| 提交半成品 | 捕获异常后回滚题库并清理文件 |

## 明确限制

- 文本框、嵌入对象和复杂 VML 内容当前不做内容级还原，只能明确报告为不支持。
- EMF/WMF 图片不会假装可显示；需要转换为 Android 可解码的位图格式后重新导入。
- 智能识别是外部模型服务，可能失败、限流或产生费用；应用只能通过本地校验降低错误，不能保证所有复杂文档都被正确识别。
- 图片二进制不会发送给文字模型，因此答案依赖图片语义的题目需要人工检查。
- 少量旧解析辅助类型尚未从仓库物理删除，但对比模式、运行时开关及其产品路由已删除；普通 UI、Debug 与 Release 均无法进入旧链路。

## 回归关注点

后续改动至少应持续覆盖：标准格式完全离线、智能模式全文覆盖、一段多题、集中答案区、自动编号、表格、多图、文件末尾收束、坏 JSON/空响应、来源编造拒绝、缓存语义、Room 迁移、取消清理、删除题库图片清理，以及普通界面不出现内部策略名称。
